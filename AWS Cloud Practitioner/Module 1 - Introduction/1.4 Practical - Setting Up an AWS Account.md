# 1.4 Practical: How to Set Up an AWS Account

A step-by-step guide to creating an AWS account **safely**, so it can't run up a surprise bill or be broken into.

> ⚠️ AWS changes its sign-up pages and Free Tier offers from time to time. If a screen looks different, follow what AWS shows you. The safety steps (MFA, a budget alert, and not using the root user) always apply.

## Part 1: Create the account

1. Go to **[aws.amazon.com](https://aws.amazon.com)** and click **Create an AWS Account**.
2. Enter an **email address** and an **account name** (for example "juan-learning").
   - This email becomes the **root user**, the account's all-powerful owner. Use an email you'll always have access to.
3. **Verify the email** with the code AWS sends, then create a **strong, unique password**. Save it in a password manager.
4. Choose a **Personal** account and enter your contact details.
5. Enter a **payment card**. AWS needs one even for free use. It may place a small temporary charge to check the card.
6. **Verify your phone number** with the text or call.
7. Choose a plan:
   - New accounts can choose a **Free plan**, which gives you free **credits** to try services for a limited time, and doesn't charge your card while you're on it.
   - Choose the Free plan while learning, and read what the page says it includes.
8. Choose the **Basic support plan**, which is free.
9. Sign in to the **AWS Management Console**.

## Part 2: Secure the root user with MFA (do this straight away)

**MFA** (multi-factor authentication) means signing in needs your password **and** a code from your phone.

1. Click your **account name** (top right), then **Security credentials**.
2. Under **Multi-factor authentication (MFA)**, click **Assign MFA device**.
3. Give it a name, choose **Authenticator app**, and scan the QR code with an app like Google Authenticator or Microsoft Authenticator.
4. Enter **two codes in a row** from the app, then click **Add MFA**.

## Part 3: Set a budget alert (so there are no surprise bills)

1. Search for **Billing and Cost Management** in the top search bar, then open **Budgets**.
2. Click **Create budget**, then choose the **Zero spend budget** template.
3. Enter your email address and click **Create budget**.
4. AWS will now email you if anything starts costing money.

## Part 4: Stop using the root user day to day

The root user can do *anything*, including closing the account, so it should only be used for a few account-level jobs. Make a separate admin user for daily work:

1. Open **IAM Identity Center** (search for it), choose your region, and click **Enable**.
2. Go to **Users**, then **Add user**. Enter a username and your email.
3. Create a **group** called `Admins`, and give it the **AdministratorAccess** permission set for your account.
4. Accept the email invitation, set the new user's password, and add MFA to it as well.
5. From now on, sign in with this user through the **AWS access portal** link in the email, not the root user.

## Checklist

- [ ] Account created, with a strong password saved in a password manager
- [ ] MFA on the root user
- [ ] Zero spend budget alert created
- [ ] Separate admin user created, with MFA
- [ ] Signed out of the root user

## Why this matters for the exam

These steps are exam topics:

- **Root user best practices** (Domain 2): enable MFA, don't use it for everyday tasks, and don't create access keys for it.
- **IAM** (Domain 2): users, groups and permissions.
- **AWS Budgets** (Domain 4): set alerts for cost or usage.
