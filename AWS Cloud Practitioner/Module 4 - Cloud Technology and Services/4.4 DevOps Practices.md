# 4.4 DevOps Practices

**DevOps** brings development and operations together, to release software **faster and more reliably** through **automation**.

## Key practices

| Practice | Meaning |
|---|---|
| **Continuous integration (CI)** | Developers merge code often, and every change is **built and tested automatically** |
| **Continuous delivery / deployment (CD)** | Tested code is **released automatically**, or with one click |
| **Infrastructure as code** | Servers and networks defined in files (CloudFormation or CDK), not clicked together by hand |
| **Monitoring and logging** | Watch everything (CloudWatch and X-Ray) so problems are found fast |
| **Small, frequent changes** | Easier to test, and easier to roll back if something breaks |

## AWS developer tools

| Service | Job in the pipeline |
|---|---|
| **AWS CodePipeline** | Runs the whole **CI/CD pipeline**: source, then build, test and deploy |
| **AWS CodeBuild** | **Builds and tests** code (compiling, running tests) |
| **AWS CodeDeploy** | **Deploys** code to EC2, Lambda, ECS or on-premises servers |
| **AWS CodeArtifact** | Stores software **packages** (npm, pip, Maven) |
| **AWS X-Ray** | **Traces** requests through an app to find slow or failing parts |
| **AWS CodeCommit** | Git repositories. *AWS stopped offering it to new customers in 2024. Most teams use GitHub, and CodePipeline connects to it* |

**The pipeline in one line:** Source (GitHub) → **CodePipeline** → **CodeBuild** (build and test) → **CodeDeploy** (release).

## Lab 4.4.2: Create a simple VPC with CloudFormation

💰 **Free:** VPCs and subnets cost nothing.

**Lesson resource:** [`lab-files/demo-vpc.yaml`](lab-files/demo-vpc.yaml), the course's template.

### What the template builds

| Resource | Details |
|---|---|
| **`DemoVPC`** | A VPC with the address range **`10.0.0.0/16`** (65,536 IP addresses), with DNS support and DNS hostnames turned on |
| **`DemoSubnet`** | A subnet inside it, **`10.0.1.0/24`** (256 addresses), in the Region's **first Availability Zone** |
| **Outputs** | The new **VPC ID** and **Subnet ID** |

### The parts to understand

| Code | Meaning |
|---|---|
| `CidrBlock: 10.0.0.0/16` | The VPC's range of private IP addresses. `/16` means the first two numbers (`10.0`) are fixed |
| `VpcId: !Ref DemoVPC` | **`!Ref`** links the subnet to the VPC created above, so CloudFormation builds the VPC **first** |
| `!Select [ 0, !GetAZs '' ]` | **`!GetAZs`** lists the Region's Availability Zones, and **`!Select [ 0, … ]`** picks the first one. The template works in **any Region** |
| `Tags: Name` | The names you'll see in the VPC console |

### Steps

1. Save the template as `demo-vpc.yaml` (or use the file in `lab-files`).
2. **CloudFormation** → **Create stack** → **With new resources (standard)** → **Upload a template file** → `demo-vpc.yaml` → **Next**.
3. **Stack name:** `demo-vpc-stack` → **Next** → **Next** → **Submit**.
4. Wait for **CREATE_COMPLETE**. The **Events** tab shows the VPC being created **before** the subnet (because of `!Ref`).
5. **Outputs** tab: copy the **VPCId** and **SubnetId**.
6. Open **VPC** → **Your VPCs**: `DemoVPC` is there with `10.0.0.0/16`.
7. **Subnets**: `DemoSubnet` is there with `10.0.1.0/24`, in the first AZ (like `eu-west-2a`).

### Is the subnet public or private?

The template has **no internet gateway** and **no route to the internet**, so `DemoSubnet` is effectively **private**. Anything in it can't reach the internet. To make a **public** subnet, you'd add:
- an **internet gateway** (`AWS::EC2::InternetGateway`), attached to the VPC
- a **route table** with a route for `0.0.0.0/0` to the internet gateway, linked to the subnet

### 🧹 Clean up

CloudFormation → select `demo-vpc-stack` → **Delete**. The VPC and subnet are both removed. That's the power of infrastructure as code: **one click deletes everything the template made**.

## Exam tips

- "Automate the build, test and release process" means **CodePipeline** (CI/CD).
- "Compile code and run tests" means **CodeBuild**. "Deploy to servers" means **CodeDeploy**.
- "Find **performance bottlenecks** in a distributed app" means **X-Ray**.
