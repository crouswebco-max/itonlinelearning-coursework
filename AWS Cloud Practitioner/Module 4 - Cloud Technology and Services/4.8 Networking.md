# 4.8 Networking

## Amazon VPC (Virtual Private Cloud)

Your own **private network** in AWS. You choose its IP address range and split it into subnets.

| Part | What it is |
|---|---|
| **Subnet** | A section of the VPC, in **one Availability Zone** |
| **Public subnet** | Has a route to the **internet gateway**: for web servers and load balancers |
| **Private subnet** | No direct internet route: for databases and back-end servers |
| **Internet gateway (IGW)** | Connects the VPC to the internet |
| **NAT gateway** | Lets private subnets **reach out** to the internet (for updates), without letting the internet in |
| **Route table** | Rules for where network traffic goes |
| **Security group** | Firewall for an **instance** (stateful, allow rules only) |
| **Network ACL** | Firewall for a **subnet** (stateless, allow and deny) |
| **VPC peering** | Connects two VPCs privately |
| **AWS Transit Gateway** | A central hub connecting **many** VPCs and on-premises networks |
| **VPC endpoints** | Reach AWS services (like S3) privately, without going over the internet |

## 4.8.2 Security groups and network ACLs

| | **Security group** | **Network ACL** |
|---|---|---|
| Level | **Instance** | **Subnet** |
| Rules | **Allow only** | **Allow and deny** |
| State | **Stateful** (replies allowed automatically) | **Stateless** (replies need their own rule) |
| Rule order | All rules are checked together | Checked **in number order**, lowest first, and the first match wins |
| Default | Denies all incoming traffic | The default NACL allows all traffic |

**Picture it:** the **NACL** is the guard at the **gate of the estate** (the subnet), and the **security group** is the lock on **each house's front door** (the instance).

## Connecting to on-premises

| Service | Meaning |
|---|---|
| **AWS Site-to-Site VPN** | Encrypted, over the internet, quick to set up |
| **AWS Client VPN** | For individual users' devices |
| **AWS Direct Connect** | A private, dedicated line: consistent speed, and it doesn't use the internet |

## Edge and delivery services

| Service | What it does |
|---|---|
| **Amazon CloudFront** | **CDN**: caches content at **edge locations** close to users, for faster websites. Works with Shield and WAF |
| **AWS Global Accelerator** | Uses AWS's global network to route users to the **nearest healthy endpoint**, with fixed IP addresses |
| **Amazon API Gateway** | Creates and manages **APIs** in front of Lambda and other services |
| **Elastic Load Balancing** | Spreads traffic across targets (see 4.6) |

## 4.8.3 Amazon Route 53

AWS's **DNS** service. It turns names like `example.com` into IP addresses. It can also **register domains** and run **health checks**.

| Routing policy | Sends users |
|---|---|
| **Simple** | To one resource |
| **Weighted** | Split by percentage, for example 90% old version and 10% new version |
| **Latency-based** | To the Region with the **lowest latency** for them |
| **Failover** | To a backup if the main site is unhealthy (active-passive) |
| **Geolocation** | By the **user's location**, for example EU users to the EU site |
| **Geoproximity** | By distance, with an adjustable bias |
| **Multivalue answer** | Returns several healthy IP addresses |

(Route 53 is named after port **53**, the DNS port.)

## Exam tips (4.8.4)

- "**Block** a specific IP address" means a **network ACL**.
- "Instance-level firewall" means a **security group**.
- "Private servers need to download updates" means a **NAT gateway**.
- "**DNS**", "domain registration" and "route by latency or location" mean **Route 53**.
- "Speed up a **global** website with **caching**" means **CloudFront**.
- "Connect **many VPCs** together" means **Transit Gateway**.
