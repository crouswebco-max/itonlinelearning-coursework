# 4.6 Compute Services

## Amazon EC2 (Elastic Compute Cloud)

**Virtual servers** in the cloud. **IaaS**: you choose the operating system and **you manage it** (updates and security).

| Term | Meaning |
|---|---|
| **Instance** | One virtual server |
| **AMI** (Amazon Machine Image) | A template for the server: the operating system plus software |
| **Instance type** | Its size: CPU, memory and network (like `t3.micro`) |
| **Key pair** | Used to sign in to the server securely with SSH |
| **Security group** | The firewall for the instance |
| **EBS volume** | The instance's hard drive (see 4.9) |
| **User data** | A script that runs when the server first starts |

### Instance families

| Family | Good for | Examples |
|---|---|---|
| **General purpose** | A balance: websites, small apps | `t3`, `t4g`, `m7g` |
| **Compute optimised** | Heavy processing: gaming servers, batch jobs | `c7g` |
| **Memory optimised** | Large data held in memory: big databases, caches | `r7g`, `x2` |
| **Storage optimised** | Very fast local disk access: data warehouses | `i4i` |
| **Accelerated computing** | GPUs: machine learning, graphics | `p5`, `g5` |

## 4.6.3 Scaling and elasticity

| Service | What it does |
|---|---|
| **EC2 Auto Scaling** | Adds instances when busy and removes them when quiet (**elasticity**), and replaces unhealthy ones |
| **Elastic Load Balancing (ELB)** | Spreads traffic across instances (and AZs), and only sends it to healthy ones |

| Load balancer | Use |
|---|---|
| **Application Load Balancer** | HTTP and HTTPS websites and APIs (layer 7) |
| **Network Load Balancer** | Very high performance TCP and UDP (layer 4) |
| **Gateway Load Balancer** | Third-party security appliances |

- **Vertical scaling (scale up):** a **bigger** instance.
- **Horizontal scaling (scale out):** **more** instances. That's what Auto Scaling does, and it's better for availability.

## Other compute services

| Service | What it is | Exam cue |
|---|---|---|
| **AWS Lambda** | **Serverless:** runs code when an event happens. No servers to manage, and you pay per request and millisecond. Up to **15 minutes** per run | "Run code without managing servers", "event-driven" |
| **AWS Elastic Beanstalk** | **PaaS:** upload your code, and AWS sets up the servers, load balancer and scaling | "Deploy a web app quickly without managing infrastructure" |
| **Amazon ECS** | Runs **Docker containers** (AWS's own system) | "Run containers" |
| **Amazon EKS** | Runs containers with **Kubernetes** | "Kubernetes" |
| **AWS Fargate** | **Serverless containers:** no servers to manage for ECS or EKS | "Containers without managing servers" |
| **Amazon ECR** | Stores **container images** | "Container image registry" |
| **Amazon Lightsail** | Simple virtual servers for a **low, fixed monthly price** | "Simple website, predictable price" |
| **AWS Batch** | Runs large numbers of **batch jobs** | "Batch processing" |

## 4.6.5 EC2 or Lambda?

| | **EC2** | **Lambda** |
|---|---|---|
| **Servers** | You manage them | None (serverless) |
| **Runs** | All the time, until you stop it | Only when triggered |
| **Time limit** | None | **15 minutes** per run |
| **Pricing** | Per second while running | Per request and per millisecond of run time |
| **Best for** | Long-running apps and full control | Short, event-driven tasks (like resizing an image when it's uploaded) |

## Lab 4.6.2: Launch an EC2 instance, step by step

💰 **Free tier:** use a free-tier-eligible type (the console labels them, usually `t2.micro` or `t3.micro`). **Terminate it at the end.**

1. Open **EC2** → **Launch instance**.
2. **Name:** `lab-web-server`.
3. **AMI:** **Amazon Linux 2023** (free tier eligible).
4. **Instance type:** the one marked **Free tier eligible**.
5. **Key pair:** **Create new key pair** → name `lab-key`, type **RSA**, format **.pem** → it downloads. Keep it safe. You'd only need it for SSH. This lab uses EC2 Instance Connect instead.
6. **Network settings** → **Edit**:
   - A **public IP address**: **Enable**
   - **Security group:** create one called `lab-web-sg`, with rules:
     - **SSH (22)** from **My IP** only (never "Anywhere" for SSH)
     - **HTTP (80)** from **Anywhere** (so the web page can be seen)
7. **Storage:** leave the default (8 GiB gp3 is within the free tier).
8. **Advanced details** → **User data**: paste this script, which installs a web server on first start:

```bash
#!/bin/bash
dnf install -y httpd
systemctl enable --now httpd
echo "<h1>Hello from $(hostname -f)</h1><p>Launched by Juan for the AWS Cloud Practitioner course.</p>" > /var/www/html/index.html
```

9. Click **Launch instance** → **View all instances**.
10. Wait until **Instance state** is **Running** and **Status check** shows **2/2 checks passed**.
11. **Test it:** copy the **Public IPv4 address** and open `http://THE-IP` in a browser (use **http**, not https). You'll see your Hello page.
12. **Connect:** select the instance → **Connect** → **EC2 Instance Connect** → **Connect**. A terminal opens in the browser. Try `uptime`.

**Understand what you built (4.6.2.2):**
- **Stop** keeps the instance and its disk. You aren't charged for compute while it's stopped, but the disk still counts.
- **Terminate** deletes it for good.
- The **Monitoring** tab shows CPU and network graphs from **CloudWatch**.

**🧹 Clean up:** select the instance → **Instance state** → **Terminate instance**. You can delete the `lab-web-sg` security group afterwards.

## Lab 4.6.4: Deploy a sample app with Elastic Beanstalk

💰 **Creates an EC2 instance (and possibly a load balancer) behind the scenes.** Choose the **single instance** option and a free-tier type, and **terminate the environment** when you're done.

1. Open **Elastic Beanstalk** → **Create application**.
2. **Environment tier:** **Web server environment**.
3. **Application name:** `lab-beanstalk-app`.
4. **Platform:** **Node.js** (or Python). **Application code:** **Sample application**.
5. **Presets:** **Single instance (free tier eligible)** → **Next**.
6. **Service access:** if you don't have the roles, let it create them (**Create and use new service role**, and an **EC2 instance profile**).
7. Keep the defaults → **Submit**. It takes about 5 minutes.
8. When **Health** is **Ok**, click the **Domain** link: the sample app is live.
9. Look at what Beanstalk made for you, in **EC2** (an instance and security group) and **CloudFormation** (a stack). That's **PaaS**: you gave it code, and AWS built the infrastructure.

**🧹 Clean up:** Elastic Beanstalk → your environment → **Actions** → **Terminate environment**. Then delete the application.

## Exam tips (4.6.6)

- "Full control of the operating system" means **EC2**.
- "No servers, pay per run, event-driven" means **Lambda**.
- "Upload code and AWS handles everything" means **Elastic Beanstalk**.
- "Containers without managing servers" means **Fargate**.
- "Automatically match capacity to demand" means **Auto Scaling**. "Spread traffic" means **Elastic Load Balancing**.
