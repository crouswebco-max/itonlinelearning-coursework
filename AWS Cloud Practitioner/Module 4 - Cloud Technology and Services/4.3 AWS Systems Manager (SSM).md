# 4.3 AWS Systems Manager (SSM)

**Systems Manager** lets you **see and manage your servers** (EC2 and on-premises) from one place, **without logging into each one**.

## Its main features

| Feature | What it does |
|---|---|
| **Parameter Store** | Stores settings and secrets (like a database address or an API key), plain or encrypted with KMS |
| **Run Command** | Runs a command on **many servers at once**, with no SSH needed |
| **Session Manager** | Opens a secure shell on a server in the browser, with **no SSH keys and no open port 22** |
| **Patch Manager** | Installs operating system updates automatically |
| **Fleet Manager and Inventory** | See what's installed on all your servers |
| **Automation** | Runs step-by-step runbooks, like "restart this server" |

**For a server to work with SSM** it needs the **SSM Agent** (already installed on Amazon Linux) and an **IAM role** with the **`AmazonSSMManagedInstanceCore`** policy.

## Lab 4.3.2: Parameter Store

💰 **Free:** standard parameters cost nothing.

1. Open **Systems Manager** → **Parameter Store** → **Create parameter**.
2. **Name:** `/lab/app/database-url`, **Tier:** Standard, **Type:** **String**, **Value:** `db.example.internal` → **Create parameter**.
3. Create a second one: **Name:** `/lab/app/api-key`, **Type:** **SecureString** (encrypted with KMS), **Value:** `not-a-real-key-123` → **Create**.
4. Open each one. The SecureString's value is hidden until you click **Show decrypted value**.
5. **Read them in CloudShell:**

```bash
aws ssm get-parameter --name /lab/app/database-url --query Parameter.Value --output text
aws ssm get-parameter --name /lab/app/api-key --with-decryption --query Parameter.Value --output text
aws ssm get-parameters-by-path --path /lab/app --recursive --with-decryption
```

**🧹 Clean up:** select both parameters → **Delete**.

**Parameter Store or Secrets Manager?** Parameter Store is free and simple. Secrets Manager costs money but can **rotate** secrets automatically.

## Lab 4.3.3: Run Command

💰 **Needs one free-tier EC2 instance.** Stop or terminate it afterwards.

1. **Create the role** (if you didn't in Module 3): **IAM** → **Roles** → **Create role** → **AWS service** / **EC2** → attach **`AmazonSSMManagedInstanceCore`** → name it `EC2-SSM-Role`.
2. **Launch an EC2 instance** (see [4.6 Compute](4.6%20Compute%20Services.md)): **Amazon Linux 2023**, a free-tier type, and under **Advanced details** → **IAM instance profile**, choose `EC2-SSM-Role`.
3. Wait about 5 minutes, then open **Systems Manager** → **Fleet Manager**. The instance should be listed as **Online**.
4. **Run Command** → **Run command** → search for **`AWS-RunShellScript`**.
5. **Commands:** paste the course's commands ([`lab-files/ssm-run-command.sh`](lab-files/ssm-run-command.sh)):

```bash
echo "Hello from AWS Systems Manager!" > /home/ec2-user/ssm-test.txt
ls -l /home/ec2-user
```

   - Line 1 **creates a file** called `ssm-test.txt` in the `ec2-user` home folder, containing the message.
   - Line 2 **lists the folder**, so the output shows the file was created.

6. **Targets:** **Choose instances manually** → tick your instance.
7. **Output options:** untick **Enable an S3 bucket** (not needed) → **Run**.
8. When the status is **Success**, click the **instance ID** → **Output**. You should see something like:

```
total 4
-rw-r--r--. 1 root root 32 Sep 23 14:05 ssm-test.txt
```

   The file is owned by **root**, because Run Command runs commands as root. It was created on the server **without SSH, a key pair or port 22**. That's the point of Systems Manager.

9. **Check it another way:** run a second command, `cat /home/ec2-user/ssm-test.txt`. The output shows `Hello from AWS Systems Manager!`.

**Bonus:** **Session Manager** → **Start session** gives a browser terminal on the same instance.

**🧹 Clean up:** **terminate** the EC2 instance. Keep the role if you're doing more labs.

## Exam tips

- "Manage or patch **many servers** without logging in" means **Systems Manager**.
- "Connect to an instance **without SSH keys or opening port 22**" means **Session Manager**.
- "Store **configuration values**" means **Parameter Store**.
