# 4.12 How AWS Services Work Together

Real apps combine several services, each doing one job well.

## Pattern 1: a classic web app (highly available)

```
Users → Route 53 (DNS) → CloudFront (cache and HTTPS) → Application Load Balancer
      → EC2 instances in an Auto Scaling group, across 2 AZs
      → RDS (Multi-AZ) for data  +  S3 for images and files
```

- **Route 53** finds the site. **CloudFront** speeds it up.
- The **load balancer** spreads traffic. **Auto Scaling** matches capacity to demand.
- **Two AZs** give **high availability**. **RDS Multi-AZ** fails over automatically.

## Pattern 2: serverless

```
Users → S3 (website files) or Amplify
      → API Gateway (API) → Lambda (code) → DynamoDB (data)
```

No servers to manage. Everything scales automatically, and you pay per use.

## Pattern 3: event-driven processing

```
A photo uploaded to S3 → triggers Lambda → resizes it and saves it to another bucket
                                         → SNS sends an email: "Photo ready"
```

## Pattern 4: decoupled with a queue

```
Web servers → SQS queue → worker servers process orders when they're free
```

If the workers are slow or restart, **no orders are lost**. They wait in the queue.

## Exam tips (4.12.2)

- Questions often describe **a chain of needs**. Pick the service for each link: DNS → **Route 53**, cache → **CloudFront**, spread traffic → **ELB**, scale → **Auto Scaling**, run code without servers → **Lambda**, NoSQL → **DynamoDB**, files → **S3**, decouple → **SQS**, notify → **SNS**.
- "**Highly available**" means **several AZs**. "**Disaster recovery**" means **another Region**.
- "**Least operational overhead**" usually means **serverless or managed** services.

## Lab 4.12.3: Build a mini services app

A tiny web API built from **two services working together**:

```
Browser  →  Amazon API Gateway (a web address)  →  AWS Lambda (the code)  →  "Hello from Lambda"
```

💰 **Free:** Lambda and API Gateway's free usage easily covers this.

**Lesson resource:** [`lab-files/mini-app/lambda_function.py`](lab-files/mini-app/lambda_function.py), the course's code:

```python
def lambda_handler(event, context):
    return {
        "statusCode": 200,
        "headers": {
            "Content-Type": "text/plain"
        },
        "body": "Hello from Lambda"
    }
```

### What the code means

| Part | Meaning |
|---|---|
| `def lambda_handler(event, context):` | The function Lambda runs. **`event`** holds details of the request, and **`context`** holds details about the run |
| `"statusCode": 200` | The HTTP status: **200 means OK** |
| `"headers": {"Content-Type": "text/plain"}` | Tells the browser the reply is **plain text** |
| `"body": "Hello from Lambda"` | What the browser shows |

### Part 1: Create the Lambda function

1. Open **Lambda** → **Create function** → **Author from scratch**.
2. **Function name:** `mini-services-app`.
3. **Runtime:** the latest **Python 3** (like Python 3.13).
4. **Permissions:** leave **Create a new role with basic Lambda permissions** (so it can write logs to CloudWatch) → **Create function**.
5. In the **Code** tab, open `lambda_function.py`, replace everything with the course's code → **Deploy**.
6. **Test** → **Create new test event** → name it `test` (the default JSON is fine) → **Save** → **Test**.
   The result should show `"statusCode": 200` and `"body": "Hello from Lambda"`.

### Part 2: Give it a web address with API Gateway

7. Open **API Gateway** → **Create API** → **HTTP API** → **Build**.
8. **Integrations** → **Add integration** → **Lambda** → choose `mini-services-app`.
9. **API name:** `mini-services-api` → **Next**.
10. **Configure routes:** **Method:** `GET`, **Resource path:** `/hello`, **Integration target:** `mini-services-app` → **Next**.
11. **Stages:** leave `$default` with **Auto-deploy** on → **Next** → **Create**.
12. Copy the **Invoke URL** (like `https://abc123.execute-api.eu-west-2.amazonaws.com`).

### Part 3: Try it

13. In a browser, open the invoke URL **with `/hello` on the end**:

```
https://abc123.execute-api.eu-west-2.amazonaws.com/hello
```

   The page shows **Hello from Lambda**. 🎉

14. **See it working behind the scenes:**
    - **Lambda** → `mini-services-app` → **Monitor**: a count of your requests
    - **Monitor** → **View CloudWatch logs**: a log entry for every request

### What each service did

| Service | Job |
|---|---|
| **API Gateway** | Gave the app a public **HTTPS web address**, and passed each request to Lambda |
| **Lambda** | Ran the Python code **only when someone visited**, with no servers to manage |
| **IAM** | The role let Lambda write its logs, and API Gateway was given permission to call the function |
| **CloudWatch** | Recorded the logs and metrics automatically |

This is the **serverless pattern** from the top of this page: **API Gateway → Lambda**. Add **DynamoDB** behind it, and you have a full serverless back end.

**Quicker alternative:** instead of API Gateway, a Lambda **function URL** (**Configuration** → **Function URL** → **Create**, auth **NONE**) gives the function its own web address. API Gateway is what the course pattern uses, and it adds routes, throttling and authentication.

### 🧹 Clean up

1. **API Gateway** → `mini-services-api` → **Delete**.
2. **Lambda** → `mini-services-app` → **Actions** → **Delete**.
3. **IAM** → **Roles** → delete `mini-services-app-role-…`.
4. **CloudWatch** → **Log groups** → delete `/aws/lambda/mini-services-app`.

## 4.12.4 Summary

Every AWS architecture is a set of building blocks: **compute** (EC2, Lambda), **storage** (S3, EBS), **databases** (RDS, DynamoDB), **networking** (VPC, Route 53, CloudFront) and **security** (IAM, security groups). Learn what each block is for, and the exam questions become "which block fits this need?"
