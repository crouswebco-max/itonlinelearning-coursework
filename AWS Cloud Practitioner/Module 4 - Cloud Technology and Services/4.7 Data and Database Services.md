# 4.7 Data and Database Services

## Relational and non-relational databases

| | **Relational (SQL)** | **Non-relational (NoSQL)** |
|---|---|---|
| **Data shape** | **Tables** with fixed columns, linked together | Flexible: **key-value**, documents, graphs and more |
| **Query** | SQL, with joins between tables | Simple lookups by key, very fast |
| **Scales by** | Mostly a bigger server (vertical) | Adding more servers (horizontal) |
| **Good for** | Orders, accounts, anything with relationships | Very high traffic, flexible data, shopping carts, gaming |
| **AWS** | **RDS**, **Aurora** | **DynamoDB** |

## Database services

| Service | Type | Key facts |
|---|---|---|
| **Amazon RDS** | Relational, **managed** | MySQL, PostgreSQL, MariaDB, Oracle, SQL Server. AWS handles patching, backups and failover. **Multi-AZ** gives high availability, and **read replicas** give read performance |
| **Amazon Aurora** | Relational, AWS-built | MySQL- and PostgreSQL-compatible, **faster**, and stores 6 copies across 3 AZs. **Aurora Serverless** scales automatically |
| **Amazon DynamoDB** | NoSQL key-value | **Serverless**, responds in **single-digit milliseconds** at any size. **Global tables** replicate across Regions |
| **Amazon ElastiCache** | In-memory cache | Redis, Valkey or Memcached. Puts frequently used data **in memory**, taking load off the database |
| **Amazon MemoryDB** | In-memory database | Redis-compatible, and durable |
| **Amazon Redshift** | Data warehouse | **Analytics** on huge amounts of data (OLAP), not for running apps |
| **Amazon DocumentDB** | Document database | MongoDB-compatible |
| **Amazon Neptune** | Graph database | Relationships, like social networks and recommendations |
| **Amazon Keyspaces** | Wide-column | Apache Cassandra-compatible |
| **Amazon Timestream** | Time-series | Sensor readings, metrics over time |

**Running a database yourself on EC2** means you do all the patching and backups. **RDS** means AWS does it. That's the shared responsibility model again.

## Exam tips (4.7.2)

- "Managed relational database" means **RDS**. "High performance, MySQL- or PostgreSQL-compatible" means **Aurora**.
- "NoSQL, serverless, millisecond latency at any scale" means **DynamoDB**.
- "**Cache** results to speed up the database" means **ElastiCache**.
- "Analytics and **data warehouse**" means **Redshift**.
- "**Automatic failover** to another AZ" means **RDS Multi-AZ**. "**Scale reads**" means **read replicas**.
- "**Migrate a database** to AWS" means **Database Migration Service (DMS)**.

## Lab 4.7.3: Launch a free-tier RDS database

💰 **A free-tier template exists, but a database left running keeps costing.** Delete it at the end.

1. Open **RDS** → **Create database** → **Standard create**.
2. **Engine:** **MySQL** (or PostgreSQL).
3. **Templates:** **Free tier**.
4. **DB instance identifier:** `lab-db`. **Master username:** `admin`. Choose **Self managed** and set a password (or let AWS manage it in Secrets Manager).
5. **Instance class:** the free-tier one (such as `db.t4g.micro` or `db.t3.micro`).
6. **Storage:** 20 GiB. **Untick storage autoscaling.**
7. **Connectivity:** **Public access: No** (the safest choice).
8. **Additional configuration:** initial database name `labdb`. Untick **backups** and **encryption** only if the free-tier template asks (for learning only).
9. **Create database**. It takes 5–10 minutes.
10. Open `lab-db` and look at the **Endpoint** (the address apps connect to), **Monitoring** (CloudWatch graphs), **Maintenance and backups**, and **Configuration** (Multi-AZ: No).

**🧹 Clean up:** select `lab-db` → **Actions** → **Delete** → untick **Create final snapshot** and **Retain automated backups** → type `delete me` → **Delete**.

## Lab 4.7.4: NoSQL databases

NoSQL tables don't have fixed columns. Each item can have different attributes, and you find items by their **key**:

| Key part | Meaning |
|---|---|
| **Partition key** | The main key, which decides where the item is stored (like `userId`) |
| **Sort key** (optional) | Orders items that share a partition key (like `orderDate`) |

**NoSQL Workbench** is a free desktop app from AWS for designing DynamoDB tables and trying queries before building them. It's useful for planning your keys.

## Lab 4.7.5: DynamoDB: create a table and add items

💰 **Free:** DynamoDB's free tier covers small tables like this.

1. Open **DynamoDB** → **Tables** → **Create table**.
2. **Table name:** `Movies`. **Partition key:** `title` (String). **Sort key:** `year` (Number).
3. **Table settings:** **Default settings** → **Create table**. Wait for it to be **Active**.
4. **Explore items** → `Movies` → **Create item**:
   - `title` = `Paper Kingdoms`, `year` = `2022`
   - **Add new attribute** → String `genre` = `Animation`
   - **Add new attribute** → Number `rating` = `8.8`
   - **Create item**
5. Add a second item with **different attributes**, for example no `rating` but a `director`. NoSQL allows this.
6. **Query:** choose **Query** → `title` = `Paper Kingdoms` → **Run**.
7. **With CloudShell:**

```bash
aws dynamodb put-item --table-name Movies --item '{"title":{"S":"Wild Tide"},"year":{"N":"2024"},"genre":{"S":"Adventure"}}'
aws dynamodb scan --table-name Movies
```

**🧹 Clean up:** select `Movies` → **Delete**. Keep it if you're doing the mini app in 4.12, which uses its own table.
