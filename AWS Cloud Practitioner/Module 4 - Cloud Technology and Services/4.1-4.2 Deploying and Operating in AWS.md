# 4.1–4.2 Deploying and Operating in AWS

**Cloud Technology and Services** is Domain 3, the biggest domain (**34%**). It's mostly about knowing **which service does what**.

## Ways to create and manage resources

| Method | Best for |
|---|---|
| **AWS Management Console** | Learning, exploring, and one-off jobs |
| **AWS CLI** | Scripts and repeated tasks from a terminal |
| **AWS SDKs** | Working with AWS from inside your own code |
| **Infrastructure as code (IaC)** | Building the same setup again and again, reliably |

## Infrastructure as code

You describe your resources in a **file (a template)**, and AWS builds them for you.

| Tool | What it is |
|---|---|
| **AWS CloudFormation** | Write templates in **YAML or JSON**. AWS creates everything as a **stack**, and can update or delete it all together |
| **AWS CDK** (Cloud Development Kit) | Write infrastructure in a **programming language** (TypeScript, Python and others). It turns into CloudFormation |

**Why use infrastructure as code:**
- **Repeatable:** the same template gives the same result every time, whether for dev, test or production.
- **Version-controlled:** keep templates in Git and see what changed.
- **Fast and safe:** delete a stack and everything in it is removed, with nothing left behind to cost money.

## Connecting to AWS

| Option | Meaning |
|---|---|
| **Public internet** | The normal way: the Console, the CLI, websites |
| **AWS Site-to-Site VPN** | An **encrypted** connection over the internet between your office and AWS. Quick to set up |
| **AWS Direct Connect** | A **private, dedicated** network line from your data centre to AWS. More consistent speed, and it doesn't use the internet |

## Lab 4.2.2: Launch a simple CloudFormation stack

💰 **Free:** the template creates one empty S3 bucket.

**Lesson resources:** the course gives two templates for this lesson:
1. [`lab-files/cf-demo-bucket.yaml`](lab-files/cf-demo-bucket.yaml): an S3 bucket (Part A, below)
2. [`lab-files/demo-vpc.yaml`](lab-files/demo-vpc.yaml): a VPC with one subnet (Part B, below). It's the same template used again in Lab 4.4.2

### Part A: the S3 bucket stack

The course's template:

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Description: Create a demo S3 bucket
Resources:
  DemoBucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: !Sub "cf-demo-bucket-${AWS::AccountId}-${AWS::Region}"
Outputs:
  BucketName:
    Value: !Ref DemoBucket
```

### What the template means

| Part | Meaning |
|---|---|
| `AWSTemplateFormatVersion` | The template format version (always `2010-09-09`) |
| `Description` | A note about what the stack does |
| `Resources` | What to create. Here, one resource called `DemoBucket` |
| `Type: AWS::S3::Bucket` | The kind of resource: an S3 bucket |
| `!Sub "cf-demo-bucket-${AWS::AccountId}-${AWS::Region}"` | **Substitutes** your account ID and Region into the name, like `cf-demo-bucket-123456789012-eu-west-2`, so it's always **globally unique** |
| `Outputs` | Values shown after the stack is created |
| `!Ref DemoBucket` | For a bucket, **returns its name** |

### Steps

1. Save the template to your computer as `cf-demo-bucket.yaml` (or use the file in `lab-files`).
2. Open **CloudFormation** → **Create stack** → **With new resources (standard)**.
3. **Choose an existing template** → **Upload a template file** → choose `cf-demo-bucket.yaml` → **Next**.
4. **Stack name:** `cf-demo-stack` → **Next** → leave the options as they are → **Next** → **Submit**.
5. Watch the **Events** tab: `CREATE_IN_PROGRESS`, then `CREATE_COMPLETE`.
6. **Resources** tab: shows `DemoBucket` and its real name.
7. **Outputs** tab: shows `BucketName`.
8. Open **S3**: the `cf-demo-bucket-…` bucket is there. It was created from the template, not by hand.

**If it fails with "already exists":** a bucket with that name already exists, perhaps because you ran the lab before. Delete the old bucket (or stack) and try again.

### Part B: the VPC stack

The second template builds a **VPC** (`10.0.0.0/16`) with **one subnet** (`10.0.1.0/24`) in the Region's first Availability Zone.

1. **CloudFormation** → **Create stack** → **With new resources (standard)** → **Upload a template file** → `demo-vpc.yaml` → **Next**.
2. **Stack name:** `demo-vpc-stack` → **Next** → **Next** → **Submit**.
3. Wait for **CREATE_COMPLETE**, then check the **Outputs** tab (**VPCId** and **SubnetId**) and the **VPC** console (`DemoVPC` and `DemoSubnet`).

The template is explained line by line in [Lab 4.4.2](4.4%20DevOps%20Practices.md).

**Notice:** two templates, two stacks, and two completely different kinds of resource, all created the same way. That's what makes CloudFormation so useful.

### 🧹 Clean up

1. CloudFormation → select `cf-demo-stack` → **Delete**. The bucket is deleted with it.
   ⚠️ CloudFormation **can't delete a bucket that has files in it**. If you uploaded anything, **empty the bucket** in S3 first.
2. CloudFormation → select `demo-vpc-stack` → **Delete**. The VPC and subnet are removed. (Or keep it for Lab 4.4.2 and delete it after that.)

## Exam tips

- "Build the same infrastructure repeatedly" or "**infrastructure as code**" means **CloudFormation**.
- "Infrastructure in a **programming language**" means **AWS CDK**.
- "A **private, dedicated** connection" means **Direct Connect**. "**Encrypted** over the internet" means **Site-to-Site VPN**.
