# 4.9 Storage Services

## The three types of storage

| Type | How it works | AWS service |
|---|---|---|
| **Object** | Whole files, stored with metadata and fetched by a key (a URL). Can't edit part of a file | **Amazon S3** |
| **Block** | A raw disk split into blocks, used like a hard drive by **one server** | **Amazon EBS** |
| **File** | A shared file system with folders, used by **many servers at once** | **Amazon EFS**, **Amazon FSx** |

## Amazon S3 (Simple Storage Service)

- Stores **objects** (files up to 5 TB) in **buckets**. Bucket names are **globally unique**.
- **11 nines (99.999999999%) of durability**: data is copied across several AZs.
- Uses: website files, backups, data lakes, and **static website hosting**.
- **Block Public Access** is on by default. Keep it on unless you're hosting a public website.

### S3 storage classes (heavily tested)

| Class | For data that is… | Notes |
|---|---|---|
| **S3 Standard** | Used **often** | The default, and the fastest |
| **S3 Intelligent-Tiering** | Used an **unknown or changing** amount | Moves data between tiers automatically to save money |
| **S3 Standard-IA** (Infrequent Access) | Used **rarely**, but needed **quickly** | Cheaper storage, with a charge to retrieve |
| **S3 One Zone-IA** | Rarely used and **easy to recreate** | Stored in **one AZ only**, so cheaper but less resilient |
| **S3 Glacier Instant Retrieval** | Archived, but needed **instantly** (a few times a year) | Millisecond access |
| **S3 Glacier Flexible Retrieval** | Archived, and **minutes to hours** is fine | Cheaper |
| **S3 Glacier Deep Archive** | Kept for **years** (like legal records) | The **cheapest**. Retrieval takes up to 12–48 hours |

### Other S3 features

| Feature | What it does |
|---|---|
| **Versioning** | Keeps every version of a file, so you can recover from deletes or overwrites |
| **Lifecycle rules** | Move files to cheaper classes, or delete them, after a set time |
| **Replication** | Copies objects to another bucket: **Cross-Region (CRR)** or **Same-Region (SRR)** |
| **S3 Transfer Acceleration** | Faster uploads from far away, using edge locations |
| **Encryption** | On by default (SSE-S3). Can use KMS keys |

## Amazon EBS (Elastic Block Store)

- **Hard drives for EC2**, attached to one instance, in the **same AZ**.
- The data **stays** when the instance stops (unlike an **instance store**, which is temporary and lost when the instance stops).
- **Snapshots** are backups of a volume, stored in S3. You can copy them to other Regions.
- Types: **gp3** (general SSD), **io2** (high-performance SSD), **st1** and **sc1** (cheaper hard drives).

## Other storage services

| Service | What it is |
|---|---|
| **Amazon EFS** | A shared **Linux** file system that grows automatically, used by many EC2 instances at once, across AZs |
| **Amazon FSx** | Managed file systems: **FSx for Windows File Server**, Lustre (high-performance computing), NetApp ONTAP and OpenZFS |
| **AWS Storage Gateway** | **Hybrid:** connects on-premises systems to cloud storage |
| **AWS Backup** | Central, automatic backups across many AWS services |
| **AWS Elastic Disaster Recovery** | Replicates servers to AWS for quick recovery |

## Exam tips (4.9.2 and 4.9.6)

- "Files for a website", "backups", "unlimited storage" means **S3**.
- "A hard drive for **one** EC2 instance" means **EBS**. "A **shared** file system for many Linux instances" means **EFS**. "Windows file shares" means **FSx for Windows**.
- "Cheapest storage for data kept for **7 years**" means **S3 Glacier Deep Archive**.
- "Unknown access patterns" means **Intelligent-Tiering**.
- "Recover files that were **accidentally deleted** or overwritten" means **S3 Versioning**.
- "Copy data to **another Region** automatically" means **Cross-Region Replication**.
- "Temporary storage that's lost when the instance stops" means an **instance store**.

## Lab 4.9.3: Create an S3 bucket

💰 **Free** for tiny files.

1. **S3** → **Create bucket** → a unique name (like `juan-lab-files-2026`) → your Region.
2. Keep **Block all public access** on, and **Bucket Versioning** off for now → **Create bucket**.
3. Open it → **Upload** → add a small text file → **Upload**.
4. Click the file and look at its **Object URL**. Opening it gives **Access Denied**, because the bucket is private. That's the safe default.
5. Use **Open** in the console instead (which uses a signed link), and you can see it.

## Lab 4.9.4: S3 Cross-Region Replication

💰 **Pennies:** tiny storage, plus a small data transfer charge.

1. You need **two buckets in different Regions** (from Lab 4.5.3.1, or make two now).
2. **Turn on Versioning in both buckets:** each bucket → **Properties** → **Bucket Versioning** → **Edit** → **Enable**. Replication needs it.
3. Open the **source** bucket (London) → **Management** → **Replication rules** → **Create replication rule**.
4. **Name:** `copy-to-virginia`. **Status:** Enabled. **Scope:** **Apply to all objects**.
5. **Destination:** **Choose a bucket in this account** → the Virginia bucket.
6. **IAM role:** **Create new role** → **Save**. If asked about replicating existing objects, choose **No** (only new uploads are copied).
7. **Upload a new file** to the source bucket. After a minute, it appears in the destination bucket. Its **Replication status** says **COMPLETED** on the source copy.

**🧹 Clean up:** delete the replication rule, empty both buckets (turn on **Show versions**, then delete everything), then delete the buckets.

## Lab 4.9.5: Amazon EBS: create, attach and snapshot a volume

💰 **Small cost while it exists.** Delete it straight after.

1. You need a running EC2 instance (Lab 4.6.2). Note its **Availability Zone** (like `eu-west-2a`).
2. **EC2** → **Volumes** → **Create volume** → type **gp3**, size **1 GiB**, **the same AZ as the instance** → **Create**.
3. Select the volume → **Actions** → **Attach volume** → choose your instance → **Attach**. Its state becomes **In-use**.
4. **Actions** → **Create snapshot** → a description like `lab snapshot` → **Create**. See it under **Snapshots**.
5. Notice that **a volume must be in the same AZ** as its instance, but a **snapshot** can be copied to any Region (**Actions** → **Copy snapshot**).

**🧹 Clean up:** detach the volume → delete it → delete the snapshot → terminate the instance.

## Lab 4.9.7: S3 Versioning, rollback and lifecycle rules

💰 **Free** for tiny files.

1. Open a bucket → **Properties** → **Bucket Versioning** → **Enable**.
2. Upload `notes.txt` containing "version 1".
3. Change the file on your computer to "version 2" and **upload it again** with the same name.
4. Turn on **Show versions**: there are **two versions** of `notes.txt`.
5. **Roll back:** select the **newest** version → **Delete** (this permanently deletes *that version*). The older "version 1" is now the current one. Open it to check.
6. **Delete marker:** with **Show versions** off, delete `notes.txt`. It disappears, but turn **Show versions** on and you'll see a **delete marker** on top. Delete the **marker** and the file comes back.
7. **Lifecycle rule:** **Management** → **Create lifecycle rule** → name `archive-old-files` → **Apply to all objects** → tick:
   - **Transition current versions** → **Standard-IA** after **30** days → **Glacier Flexible Retrieval** after **90** days
   - **Permanently delete noncurrent versions** after **365** days
   - **Create rule**

**🧹 Clean up:** delete all versions, then the bucket (or keep it for the Athena lab).
