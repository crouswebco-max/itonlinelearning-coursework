# 3.3 Labs: IAM User, CloudShell, the CLI and IAM Roles

💰 **Cost:** IAM, CloudShell and the CLI are **free**.

Sign in as your **admin user**, not the root user.

---

## Lab 3.3.3: Create an IAM user and test its access

**Goal:** make a user who can only *read* S3, and prove they can't do anything else.

1. Open **IAM** → **Users** → **Create user**.
2. **User name:** `test-readonly`.
3. Tick **Provide user access to the AWS Management Console**.
   - If AWS suggests IAM Identity Center, choose **I want to create an IAM user**.
4. Choose a **custom password**, and untick "must create a new password" (this is only a test).
5. **Permissions:** choose **Attach policies directly**, search for **`AmazonS3ReadOnlyAccess`**, and tick it.
6. Click **Next**, then **Create user**. Copy the **console sign-in URL**.
7. Open a **private browser window**, go to the sign-in URL, and sign in as `test-readonly`.
8. **Test it:**
   - Open **S3**: you can see the list of buckets. ✅
   - Open **EC2** and try to launch an instance: you get an **"not authorised"** error. ❌ Least privilege is working.
9. **Clean up:** back in your admin session, go to **IAM** → **Users**, select `test-readonly`, and click **Delete**.

## Lab 3.3.5–3.3.6: AWS CloudShell

1. In the Console's top bar, click the **CloudShell** icon (`>_`). A terminal opens at the bottom.
2. Try these commands:

```bash
aws sts get-caller-identity     # who am I signed in as?
aws s3 ls                       # list my S3 buckets
aws iam list-users              # list IAM users
aws ec2 describe-regions --query "Regions[].RegionName" --output table
```

3. Notice you didn't set up any keys. CloudShell uses your console sign-in.

## Lab 3.3.6: Set up the AWS CLI on your own computer (Mac)

1. **Install it:** download the macOS installer from [the AWS CLI install page](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html), or with Homebrew:

```bash
brew install awscli
aws --version
```

2. **Sign in, the recommended way (IAM Identity Center):**

```bash
aws configure sso
```

   Enter the **SSO start URL** (your AWS access portal link from Module 1) and your Region, then approve the sign-in in your browser.

3. **Or with access keys** (what many courses show):
   - IAM → your user → **Security credentials** → **Create access key** → **Command Line Interface (CLI)**.
   - Run `aws configure` and paste the **Access key ID**, **Secret access key**, default Region (such as `eu-west-2`) and output format (`json`).
   - ⚠️ **Never** create access keys for the root user. **Never** put keys in code or on GitHub. **Delete** the key when you've finished learning.

4. **Test it:**

```bash
aws sts get-caller-identity
```

## Lab 3.3.7: Understand and create an IAM role

**Goal:** a role an EC2 server can use to read S3, with no keys stored on the server.

1. **IAM** → **Roles** → **Create role**.
2. **Trusted entity type:** **AWS service**. **Use case:** **EC2**. This is the **trust policy**: EC2 is allowed to assume the role.
3. **Permissions:** tick **`AmazonS3ReadOnlyAccess`**. This is the **permissions policy**.
4. **Role name:** `EC2-S3-ReadOnly`, then click **Create role**.
5. Open the role and look at the two tabs:
   - **Trust relationships:** shows `"Service": "ec2.amazonaws.com"`
   - **Permissions:** shows the S3 read-only policy
6. You'll attach this role to an EC2 instance in Module 4 (**Actions** → **Security** → **Modify IAM role**).
7. **Clean up** (when you're done with Module 4): IAM → Roles → select it → **Delete**.

**Why roles beat access keys:** the credentials are temporary and rotated automatically, and there's nothing on the server to steal.
