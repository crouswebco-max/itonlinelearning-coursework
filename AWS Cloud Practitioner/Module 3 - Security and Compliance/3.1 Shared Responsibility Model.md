# 3.1 The Shared Responsibility Model

**Security and Compliance** is Domain 2 of the exam (**30%**). The most tested idea in it is the **shared responsibility model**: security is split between AWS and you.

## The one-line version

- **AWS** is responsible for security **OF** the cloud.
- **The customer (you)** is responsible for security **IN** the cloud.

## Who does what

| AWS: security OF the cloud | Customer: security IN the cloud |
|---|---|
| Physical data centres: buildings, guards, cameras | **Your data**, and whether it's encrypted |
| Hardware: servers, storage and network equipment | **Identity and access management**: users, passwords, MFA and permissions |
| The global infrastructure: Regions, Availability Zones and edge locations | **Operating system patches on EC2** |
| The virtualisation layer (hypervisor) | **Network and firewall settings**: security groups and network ACLs |
| The software behind **managed services** (like the RDS database engine, or S3) | **Application code** and its security |
| | **Client-side encryption**, and protecting data in transit |

**Memory trick:** if you can **touch it, configure it or type into it**, it's yours. If it's in the building or under the service, it's AWS's.

## 3.1.4 How responsibilities change with the service

The more **managed** the service, the more AWS does and the less you do.

| Service type | Example | Who patches the operating system? | What you still own |
|---|---|---|---|
| **IaaS** (unmanaged) | **Amazon EC2** | **You** | The operating system, apps, security groups and data |
| **Managed service** | **Amazon RDS** | **AWS** (the database engine and operating system) | Database users, network access, backups settings and data |
| **Serverless** | **AWS Lambda**, **Amazon S3**, **DynamoDB** | **AWS** | Your code, permissions and data |

**You are always responsible for your data and who can access it,** whatever the service.

## Shared controls (both sides)

| Control | AWS's part | Your part |
|---|---|---|
| **Patch management** | Patches the infrastructure | Patches your guest operating system and apps |
| **Configuration management** | Configures its infrastructure | Configures your operating systems, databases and apps |
| **Awareness and training** | Trains AWS staff | Trains your own staff |

## Exam tips (3.1.3 and 3.1.5)

- "Who patches the operating system on an **EC2** instance?" **The customer.**
- "Who patches the operating system on **RDS**?" **AWS.**
- "Who is responsible for the **physical security** of data centres?" **AWS.**
- "Who configures **security groups**?" **The customer.**
- "Who manages **IAM users and their permissions**?" **The customer.**
- "Who is responsible for **encrypting data**?" **The customer** (AWS gives you the tools, like KMS).

## 3.1.6 Practical exercise: sort the responsibilities

Cover the right-hand column and decide: **AWS**, **Customer** or **Both**.

| Task | Answer |
|---|---|
| Replacing a failed hard drive in a data centre | AWS |
| Choosing who can read an S3 bucket | Customer |
| Installing security updates on an EC2 Linux server | Customer |
| Updating the MySQL engine version on RDS during maintenance | AWS |
| Turning on MFA for users | Customer |
| Protecting the network cables between Availability Zones | AWS |
| Encrypting a DynamoDB table's data with your own KMS key | Customer |
| Patch management | Both |
| Training staff on security | Both |
| Writing secure Lambda function code | Customer |
