## Lab 3.4.4: Configure AWS WAF with a sample rule

**Goal:** put a web server behind an **Application Load Balancer (ALB)**, protect it with **AWS WAF**, and prove a WAF rule blocks bad requests.

```
Browser → Application Load Balancer (+ AWS WAF web ACL) → EC2 web server
```

💰 **Cost:** the EC2 instance can be free tier, but the **load balancer** (about $0.02–0.03 an hour) and the **WAF web ACL** ($5 a month plus $1 per rule, charged by the hour) cost money while they exist. Do the lab in one sitting, then **clean up**. It should cost well under $1.

**Lesson resource:** [`lab-files/waf-demo-user-data.sh`](lab-files/waf-demo-user-data.sh). This is the course's script, with the `echo` line fixed so it works.

### Part 1: Launch the web server

1. **EC2** → **Launch instance** → **Name:** `waf-demo-web`.
2. **AMI:** **Amazon Linux 2023**. **Instance type:** free-tier eligible.
3. **Key pair:** **Proceed without a key pair** (you won't need to log in).
4. **Network settings** → **Edit** → create a security group `waf-demo-web-sg` allowing **HTTP (80)** from **Anywhere**.
5. **Advanced details** → **User data:** paste the whole script from `waf-demo-user-data.sh`.
6. **Launch instance**. When it's **Running** with **2/2 checks passed**, open `http://ITS-PUBLIC-IP`. You should see **"Hello from AWS WAF Demo!"**.

### Part 2: Put a load balancer in front of it

WAF can't attach to an EC2 instance directly. It protects **load balancers, CloudFront, API Gateway** and a few others.

7. **EC2** → **Target groups** → **Create target group** → type **Instances** → **Name:** `waf-demo-tg` → **HTTP : 80** → **Next** → tick `waf-demo-web` → **Include as pending below** → **Create target group**.
8. **EC2** → **Load balancers** → **Create load balancer** → **Application Load Balancer**.
   - **Name:** `waf-demo-alb`. **Scheme:** Internet-facing.
   - **Network mapping:** your default VPC, and tick **at least two Availability Zones**.
   - **Security groups:** use `waf-demo-web-sg` (it allows port 80).
   - **Listener:** HTTP : 80 → **Forward to** `waf-demo-tg`.
   - **Create load balancer**.
9. Wait until the state is **Active** (a few minutes). Copy its **DNS name** and open `http://THE-DNS-NAME`: the same Hello page, now through the load balancer.

### Part 3: Create the WAF web ACL with a sample rule

10. **WAF & Shield** → **Web ACLs** → **Create web ACL** (use the classic wizard if asked).
11. **Resource type:** **Regional resources**. **Region:** the same as your load balancer.
12. **Name:** `waf-demo-acl`.
13. **Associated AWS resources** → **Add AWS resources** → **Application Load Balancer** → tick `waf-demo-alb` → **Add** → **Next**.
14. **Add rules** → **Add my own rules and rule groups** → **Rule builder**:
    - **Name:** `block-test-query`
    - **Type:** Regular rule. **If a request:** matches the statement
    - **Inspect:** **Query string**. **Match type:** **Contains string**. **String to match:** `attack`
    - **Action:** **Block**
    - **Add rule**
15. **Default web ACL action:** **Allow**.
16. **Next** → **Next** → **Next** → **Create web ACL**.

### Part 4: Test the rule

17. Open `http://THE-DNS-NAME`: the page loads (**allowed**).
18. Open `http://THE-DNS-NAME/?q=attack`: you get **403 Forbidden** (**blocked by WAF**).
19. In **WAF & Shield** → `waf-demo-acl` → **Overview**, the graph and **sampled requests** show the blocked request (they can take a few minutes to appear).

**Optional:** add the **AWS managed rule group** "Core rule set", which blocks common attacks like SQL injection and cross-site scripting.

### 🧹 Clean up (in this order)

1. **WAF:** `waf-demo-acl` → **Associated AWS resources** → remove the load balancer → then **Delete** the web ACL.
2. **EC2** → **Load balancers** → delete `waf-demo-alb`.
3. **EC2** → **Target groups** → delete `waf-demo-tg`.
4. **EC2** → **Instances** → **terminate** `waf-demo-web`.
5. Delete the `waf-demo-web-sg` security group (after the instance has terminated).

## Lab 3.4.5: Enable AWS Security Hub

> ### ⚠️ Course notice: don't enable Amazon Inspector
> The course video also enables **Amazon Inspector** (vulnerability scanning for EC2 instances and container images). Since the video was recorded, **Inspector has been removed from the AWS Free Tier**, so turning it on may cost money.
>
> **What to do:** **watch** the Inspector part of the video to see how it works and how it feeds findings into Security Hub, but **don't enable Inspector yourself**. Follow along with the **Security Hub** part only.
>
> *If you want to try Inspector later, AWS offers a 15-day free trial the first time it's enabled in an account. Check the current pricing page before turning it on.*

💰 **Cost:** Security Hub has a **30-day free trial** per account per Region, then charges per security check. It can also switch on **AWS Config**, which has its own small charges. Disable both when you're finished.

*AWS has been updating Security Hub, so in the console the classic version may be called **Security Hub CSPM**. The steps are similar.*

1. Open **Security Hub**, then **Go to Security Hub** (or **Get started**).
2. Leave **AWS Foundational Security Best Practices** ticked, and click **Enable Security Hub**.
3. **If you see an option to enable Amazon Inspector, leave it off** (see the notice above).
4. Wait a while (checks can take hours), then explore the dashboard:
   - **Summary:** your overall **security score**, and findings grouped by severity
   - **Security standards:** how your account scores against **AWS Foundational Security Best Practices**. These are the **compliance findings**
   - **Findings:** individual issues, like "root user has no MFA" or "S3 bucket allows public access"
   - **Integrations:** the services that send findings in: **GuardDuty**, **Inspector**, **Macie**, **Config** and others
5. Click a finding to see its **severity**, the **resource** affected, and the **remediation** steps.

### What to remember for the exam

| Service | Job | How it links to Security Hub |
|---|---|---|
| **Amazon Inspector** | Scans EC2, container images and Lambda for **software vulnerabilities** | Sends vulnerability findings to Security Hub |
| **Amazon GuardDuty** | **Detects threats** and suspicious activity | Sends threat findings |
| **Amazon Macie** | Finds **sensitive data** in S3 | Sends data findings |
| **AWS Config** | Records configuration and checks rules | Powers many of Security Hub's compliance checks |
| **AWS Security Hub** | **Collects all the findings in one place** and scores you against security standards | The central dashboard |

**🧹 Clean up:** **Settings** → **General** → **Disable Security Hub**. If it switched on AWS Config, open **AWS Config** → **Settings** and **stop the recorder**. Check that Inspector is **not** enabled (open **Inspector**: it should offer "Get started", not show a dashboard).

## Lab 3.4.6: Store and retrieve a secret with AWS Secrets Manager

💰 **Cost:** $0.40 per secret per month (new secrets get a **30-day free trial**), plus a tiny charge per API call. Delete the secret when you're done.

**Lesson resource:** [`lab-files/secrets-manager-commands.sh`](lab-files/secrets-manager-commands.sh). This is the course's CLI command, with a typo fixed (see step 8).

### Store the secret

1. Open **Secrets Manager** → **Store a new secret**.
2. **Secret type:** **Other type of secret**.
3. Add key/value pairs, made up and **never real**:
   - `username` = `demo_user`
   - `password` = `ExamplePassword123!`
4. **Encryption key:** leave it as `aws/secretsmanager` (the key AWS manages) → **Next**.
5. **Secret name:** `DemoCredentials` (it must match the name in the command) → **Next**.
6. **Rotation:** leave it off → **Next** → **Store**.

### Retrieve it

7. **In the console:** open `DemoCredentials` → **Retrieve secret value**. The username and password appear.
8. **With the CLI:** open **CloudShell** (the `>_` icon in the top bar) and run:

```bash
aws secretsmanager get-secret-value --secret-id DemoCredentials
```

   ⚠️ The course's copy says `--select-id`. That's a **typo**, and the CLI answers with an "unknown options" error. The correct option is **`--secret-id`**.

   You get back JSON with the secret's **ARN**, **Name**, **VersionId** and the **SecretString** (your username and password).

9. To get just the value:

```bash
aws secretsmanager get-secret-value --secret-id DemoCredentials --query SecretString --output text
```

### Why it matters

- Apps ask Secrets Manager for the password **when they run**, so it's **never written in the code** or saved on GitHub.
- Access is controlled by **IAM**: only users and roles with `secretsmanager:GetSecretValue` can read it.
- Every read is logged in **CloudTrail**.
- Secrets Manager can **rotate** the password automatically. That's its big difference from Systems Manager Parameter Store.

### 🧹 Clean up

Open `DemoCredentials` → **Actions** → **Delete secret**. AWS waits at least 7 days before deleting it, in case you change your mind. To delete it straight away, run this in CloudShell:

```bash
aws secretsmanager delete-secret --secret-id DemoCredentials --force-delete-without-recovery
```
