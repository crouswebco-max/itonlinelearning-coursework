# 2.3 What is Cloud Computing?

**Cloud computing** is the **on-demand delivery of IT resources over the internet with pay-as-you-go pricing.**

Instead of buying and running your own servers, you rent computing power, storage and databases from a provider like AWS, use them when you need them, and pay only for what you use.

## Five key ideas

| Idea | Meaning |
|---|---|
| **On-demand** | Get resources in minutes, whenever you want, without asking anyone |
| **Over the internet** | Use them from anywhere |
| **Pay-as-you-go** | Pay only for what you use, like an electricity bill |
| **Elastic** | Scale up when busy, and back down when quiet |
| **Managed by the provider** | AWS looks after the buildings, hardware and much more |

## Cloud service models: how much you manage

| Model | You manage | The provider manages | AWS example |
|---|---|---|---|
| **IaaS**: Infrastructure as a Service | The operating system, apps and data | The hardware, network and data centre | **Amazon EC2** (virtual servers) |
| **PaaS**: Platform as a Service | Your app and data | Everything underneath, including the operating system | **AWS Elastic Beanstalk** |
| **SaaS**: Software as a Service | Just using it | Everything | Gmail, Microsoft 365 |

**Remember:** IaaS gives the most control, SaaS the least. The more control you have, the more you're responsible for.

## Cloud deployment models: where it runs

| Model | Meaning |
|---|---|
| **Cloud** (public cloud) | Everything runs in the cloud, for example a new app built entirely on AWS |
| **Hybrid** | Some parts on-premises and some in the cloud, connected together. Common during a migration, or when some data has to stay in-house |
| **On-premises** (private cloud) | Everything in your own data centre, using cloud-style tools |

## 2.3.2 Practical: a first look at the AWS Console

A safe tour, with nothing that costs money:

1. Sign in to the **AWS Management Console** (with the admin user from Module 1, not the root user).
2. Look at the **Region** selector (top right, next to your account name). AWS runs in many **Regions** around the world, like `eu-west-2` (London) and `us-east-1` (N. Virginia). Most resources live in one Region.
3. Pick the Region closest to you. It's usually the fastest and often the right choice for your data.
4. Use the **search bar** to find a service (try "EC2", "S3" and "IAM"). Notice that **IAM** says **Global**: some services aren't tied to one Region.
5. Open the **services menu** (the grid icon) to see the service categories: Compute, Storage, Database, Networking, Security and more.

**Exam point:** choosing a Region depends on **compliance** (data laws), **latency** (closeness to users), **service availability** (not every service is in every Region) and **pricing** (it varies by Region).
